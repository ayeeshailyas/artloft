# The Artloft - Project Context

## Brand
**The Artloft** is a handmade crochet brand run by a single artist-owner. Logo: a mulberry ball of yarn with a wooden needle and a crochet hook inside a double ring (`images/logo.png`).

**Products:** crochet flowers, bouquets, sunflowers, flower pot covers, handbags, tote bags, keychains, bookmarks, bracelets, and fully custom pieces on request.

## Goal
A simple, minimal, sleek and elegant storefront with a quiet, upmarket feel. Customers browse, add items to a bag, and send their order straight to the owner on WhatsApp. No payment gateway, no backend.

## Design system
| Role | Value |
|---|---|
| Primary accent (Deep Mulberry) | `#781845` |
| Secondary accents (Dusty Rose / Terracotta) | `#C47B89`, `#B85C38` |
| Canvas (Atelier Off-White / Pale Cream) | `#FFF8F8`, `#FFF0F4` |
| Text (Deep Espresso) | `#2B2125` |

- Headings: **Cormorant Garamond** (serif). Body: **Jost** (sans). Both are bundled locally in `fonts/` (no Google Fonts requests).
- Style: generous whitespace, thin rose borders, round pill buttons, one bold mulberry section (custom orders), calm motion (drawer slide only).

## Tech
- HTML + Tailwind CSS 3 (compiled with the Tailwind CLI) + vanilla JavaScript.
- No frameworks, no backend, no third-party scripts, no CDN, no external images.

## Pages
| File | Purpose |
|---|---|
| `index.html` | Home: animated hero, category marquee, 3 featured pieces, custom-order banner, how to order |
| `shop.html` | Full collection with category filters (`shop.html#Bouquets` opens a category) |
| `custom.html` | Custom order request form (sent to WhatsApp) |

## Motion
Hero entrance (staggered text rise, arch image reveal, thread line drawing, floating rotating logo seal), scrolling category marquee, scroll reveals, card lift and image zoom, button and filter transitions, bag badge pop, add-to-bag toast, page fade between pages. All motion is disabled for visitors who prefer reduced motion.

## How ordering works
1. Customer adds products to the bag (header "Bag" opens the checkout page).
2. On the checkout page they enter name, phone, delivery address, payment method (cash on delivery, bank transfer, Easypaisa / JazzCash) and optional notes.
3. "Place order on WhatsApp" opens `wa.me/<number>` with a pre-written order message (items, quantities, subtotal, details).
4. The owner confirms delivery charges and payment details in the chat.

Custom requests use the form on `custom.html` and are sent to WhatsApp the same way.

## Setup checklist
1. Open `js/config.js` and set `whatsappNumber` (digits only, with country code, e.g. `923001234567`).
2. Edit `js/products.js`: names, descriptions, prices.
3. Drop photos into `images/products/` using the file names in `js/products.js`.
4. If you change classes in `index.html` or `js/*.js`, run `npm run build`.
5. Open `index.html` in a browser, or host the folder on any static host (Netlify, Vercel, GitHub Pages, Cloudflare Pages).

## Security approach
- Strict Content-Security-Policy (meta tag): only same-origin scripts, styles, fonts and images; no inline scripts or styles; no network requests (`connect-src 'none'`); forms cannot submit anywhere.
- Customer or product data is only ever inserted with `textContent`. The only HTML injected is the fixed header/footer markup in `js/layout.js`, which contains no user data.
- All user input is trimmed, stripped of control characters and `<` `>`, length-limited and validated before use.
- Prices are read only from `js/products.js`. The saved bag holds just product ids and quantities and is re-validated on load, so edited browser storage cannot change prices.
- WhatsApp opens with `noopener,noreferrer`; `referrer` policy is `no-referrer`.
- No cookies, no tracking, no analytics, no third-party code. Dependencies are dev-only (Tailwind and fonts) and pinned.
- When hosting, also enable HTTPS and send headers `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `frame-ancestors 'none'` (Netlify/Vercel can set these; a meta tag cannot).
- "100% secure" is not achievable for any website; this setup removes the common attack surface (no server, no database, no third-party code).
